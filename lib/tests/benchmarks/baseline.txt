KEY FINDINGS
────────────────────────────────────────────────────────────────────────────────

1. EXTRACTION IS THE DOMINANT STAGE
   Trafilatura HTML extraction consumes 63% of total pipeline time at ~282 µs/chunk.
   This is the primary bottleneck in blue-data-web-source and the key difference from
   blue-data-doc-source, where text parsing is near-zero cost. Enrichment (BasicEnricher
   regex) is second at 35% (~157 µs/chunk). Disabling the enricher when entity data is
   not needed roughly halves per-page pipeline cost.

2. PAGE STRUCTURE STRONGLY AFFECTS EXTRACTION SPEED
   Structured pages (h2 headers, article tags) extract 3.6× faster than unstructured
   prose (889 vs 244 pages/sec). trafilatura resolves content regions faster when the
   HTML tree has clear semantic structure. No-content pages (JS redirects) return None
   fastest — trafilatura short-circuits when the body is empty (1,133 pages/sec).

3. METADATA COVERAGE FOLLOWS PAGE STRUCTURE
   Title is extracted from all content pages (100%) — all page types include <title> in
   <head>. Date coverage requires article:published_time meta tag (100% on structured
   and mixed, 0% on unstructured). Author coverage requires meta[name=author] (100%
   on structured only). In production, expect 60–90% title and 30–60% date coverage
   depending on site type.

4. NAV-FRAGMENT REMOVAL IS EFFECTIVELY FREE AT PAGE SCALE
   The stripping pass (regex over extracted text lines) adds negligible overhead at small
   scale. At large scale across many mixed pages it contributes ~8% of extraction+strip
   time — still dominated by trafilatura. The pass is always applied at no meaningful cost.

5. CHUNKER THROUGHPUT IS UNCHANGED FROM DOC-SOURCE
   SectionChunker processes 18–23M words/sec on extracted web text, identical to its
   performance in blue-data-doc-source. The chunker sees plain text in both cases.

6. EMBEDDING DOMINATES AT PRODUCTION SCALE
   DummyEmbeddingModel (SHA-256, no network) costs ~1 µs/chunk. A real OpenAI
   text-embedding-3-small call costs ~50–150 ms per API call. At 5 chunks/page,
   embeddings will cost ~100–300× more than the entire rest of the pipeline when
   using OpenAI. Batch API calls or a local embedding model eliminate this bottleneck.
